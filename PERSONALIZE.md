### Give the actual page, not just the platform

| Destination type | What to supply |
| --- | --- |
| Instagram / TikTok / LinkedIn / YouTube / Pinterest | Full public profile or channel URL; a handle alone is not enough |
| Substack / newsletter | Exact publication, signup, or article URL; say which one you want |
| Digital newsstand / blog | Its own public URL; clarify whether this is separate from your newsletter |
| Business / personal website | Homepage or the specific service/location page visitors should land on |
| ShopMy / LTK / online shop | Exact profile, shelf, collection, product, or storefront URL |
| Booking / appointments | Public booking page, not the admin calendar |
| Podcast / music | Preferred show, episode, or artist URL and which platform should open |
| Portfolio / scrapbook / gallery | Exact public collection or archive URL |
| Download / guide / media kit | Public file or landing-page URL; a file on your computer cannot be a visitor’s link |
| Community / membership / event | Public join, ticket, registration, or information page |
| Contact | The email you are comfortable making public, a contact-form URL, or an explicitly chosen public phone number |
| Something else | Describe what visitors should reach and give its full public URL |

Email destinations use `mailto:YOUR_PUBLIC_EMAIL`; optional phone destinations use `tel:YOUR_PUBLIC_NUMBER`. These placeholders are instructions, not working links. Codex should format your real address only after you provide it.

If a destination is not ready, mark it **pending**. Keep it inactive in the preview. Supply it or remove that slot before publishing. Never fill the gap with Anna’s link, a made-up address, or a platform homepage.

## 4. Movement and opening links

- Automatic winding and return, or movement only after a click?
- Open ordinary clicks in the same tab (starter default), or another preference?
- Any specific pacing preference?

Keep a pause button and support people who have reduced motion enabled. A circle and its matching text link should always reach the same destination. Visitors should still be able to use the keyboard and normal browser actions such as Command/Ctrl-click.
